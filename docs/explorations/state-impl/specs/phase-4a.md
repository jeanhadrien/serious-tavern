STORY STATE, BACKEND (STATE-DESIGN-PROPOSAL-3 Part 2). Per-chat state that workflow turns write; it lives as long as the writing turn's replies. Web UI comes in the next phase (4b); this phase delivers shared + engine + server + API, fully tested.

STATE DEFINITIONS (records)
- Shared `stateDefinitionSchema` (passthrough): `id` (uuid), `name` (template-safe /^[A-Za-z_][A-Za-z0-9_]*$/, unique among definitions), `description?`, `keys: Record<keyName, KeyDef>` (key names template-safe too), `createdAt`, `updatedAt`. KeyDef = discriminated union on `type` (passthrough):
  - number: `default?` (number, else 0), `min?`, `max?`
  - boolean: `default?` (else false)
  - enum: `options` (non-empty string[]), `default?` (else first option)
  - text: `default?` (else '')
  - object: `default?` (else {}), optional `schema?` (ignored for now beyond being kept)
  - collection: `cap?` (int >= 1), `fields?: Record<name, 'text'|'number'|'boolean'>`; default value []
- YAML storage `data/state/definitions/<slug>.yaml` through a YamlRepository subclass + codec (same pattern as providers/presets: stamping, invalid files skipped and never modified, identity = id in file). Watcher + `stateDefinitions.changed` event with `invalidFiles` (watcher only when `watch` is on; API writes publish with a fresh listInvalid()).
- API contract (`packages/shared/src/api/state.ts` or similar): list/get/create/update/delete definitions. Rules: renaming (`name` change) a definition that any session has stored writes for → 409 `STATE_DEFINITION_IN_USE` with a plain message; deleting a definition with stored writes → 409 with the list of session titles (ids in details). Changing keys/types is always allowed (the fold tolerates it).
- Seed: one example definition `scene` (only created when missing, never overwritten; seeds are idempotent): keys `tension` number 0..10 default 3, `mood` enum [calm, uneasy, tense, release] default calm, `lastInjectionLevel` number, `injected` collection cap 30 fields { level: number, entryId: text }.

STORAGE ON THE SESSION (additive, default empty)
- `session.state = { turns: TurnEntry[] }` (default `{ turns: [] }`). TurnEntry: `{ executionId, at, completed: boolean, replies: number /* replies produced at settle */, writes: StateWrite[] }`.
- StateWrite targets either a definition key or a node's own implicit key: e.g. `{ target: { kind: 'definition', definitionId, key } | { kind: 'node', nodeId, key }, op: 'set' | 'add' | 'remove' | 'delete', value?, item?: { id, text, ...fields }, itemId?, nodeId /* writer */ }`. Scalars always store the value AFTER the write (`increment` is computed into a `set` from the turn-start value plus earlier increments of the same turn, clamped). Collections store item-level `add`/`remove`.
- An entry is appended for EVERY settled turn (even without writes), in `settleTurn`'s mutation, so turn counting is stable. Writes come from the outcome or from `ExecutionFailure` (failed/stopped turns keep the writes of completed nodes). `completed` = the run completed without error/stop.

THE FOLD (pure, in packages/shared, heavily table-tested + a randomized sequence test)
- Turn presence: a turn is present iff (entry.replies > 0 and at least one assistant message with its executionId exists in session.messages with status !== 'streaming') or (entry.replies === 0 and entry.completed). Turns whose entry is missing (sessions created before this feature) are simply not counted.
- Turn numbers: present turns numbered 1..n in order; the turn being run is n+1 (`trigger.turn`).
- Values per definition key: the post-value of the most recent present turn that wrote it (`delete` → default); never written → default. Collections: items added by present turns minus items removed by present turns, newest first, cut to `cap` (report how many were dropped by the cap).
- Validation against the CURRENT definition: a stored value that doesn't fit (type changed, out of bounds, not in options, key removed) reads as the default and produces a warning `{ definition, key, message }`; stored data is never rewritten.
- Meta per key: `written` (bool), `turnsSinceWrite` (number; never written ⇒ equals the current turn number, i.e. "written before turn 1"), `writtenAtTurn` (number | null), `count` (collections). Also a per-key history (value after each present turn that wrote it, with turn numbers) — for sparklines and `history` later; keep it cheap.
- Node implicit keys (`target.kind === 'node'`) fold the same way, keyed by node id.

ENGINE
- `executeWorkflow` options gain `state?: StateSnapshot` (the folded values + meta for definitions, the node implicit values, the definitions themselves, and the current turn number), computed by the server at turn start. `ExecutionContext.state` exposes read access (by definition id + key: value and meta; node implicit values for ctx.nodeId) and `ctx.writeState(...)` which BUFFERS writes. The executor collects buffered writes of nodes that completed (a node that errors contributes nothing), in deterministic order (wave order, then node id), and returns them with the result AND on `ExecutionFailure`. Writes must never be visible to reads within the same turn.
- Template data gains `state` (`{{state.<definitionName>.<key>}}`, values only, collections as arrays of items so `{{#each}}` works) and `trigger.turn`. Macro registry: `state` and a `state.<path>` pattern macro, `trigger.turn` (no hand-written key lists).
- Nodes (category 'State'):
  - `state-read` ('State Read'): config `definitionId`, `key`, `read: 'value' | 'meta'`. Ports via resolvePorts using `resources.stateDefinitions` (add to NodeResources, snapshotted by prepareWorkflow; the resolvePorts route passes it): value → `value` typed by key type (number/boolean/text for enum+text/object/array for collection); meta → `written` (boolean), `turnsSinceWrite` (number), `writtenAtTurn` (number, optional), `count` (number, collections only). Unknown definition/key → node error (plain message) and resolvePorts fails cleanly (edges kept, per AGENTS prune rule).
  - `state-write` ('State Write', `sink: true`): config `definitionId`, `key`, `op` (allowed ops depend on key type: number set/increment/delete; boolean/enum/text/object set/delete; collection add/remove/delete). Input `value` typed per key/op (increment: number, default 1 when unconnected; add: any — a string becomes `{ text }`, an object must have a string `text`; remove: text item id; delete: no input). Validates the value against the key (wrong type/out-of-range enum → node error; numbers are clamped to min/max). Output `value` (pass-through: the post-value; for add, the item with its id). Item ids: deterministic from the run (e.g. `${executionId}:${nodeId}:${n}`) or uuid — must be unique.
- Draw (phase 3 node) gains `avoidRecent` (int >= 0 turns, default 0 = off): when > 0, Draw records each drawn entry in its node implicit key `draws` (a collection item `{ text: entry text, entryKey }` where entryKey = collectionId + a fingerprint of the entry text, robust to derived entry ids shifting) and excludes entries drawn by present turns within the last N turns. Deleting the reply undoes the draw. The `reason` output mentions how many were excluded as recent.
- Tests: buffered/invisible writes, failure keeps completed writes, deterministic order, every op, clamping, validation errors, node implicit state, Draw avoidRecent with the fold.

SERVER
- `services/chat.ts`: at turn start (inside the existing startTurn mutation) load definitions, fold the session state, pass the snapshot; at settle, append the TurnEntry (writes from outcome or ExecutionFailure; `replies` = number of assistant messages saved for the turn; `completed`).
- Message edit (`updateMessage`): additively stamp `editedAt` on the message (display only; stored state is never recomputed).
- Message delete: unchanged (content-only); the fold recomputes presence. 
- API: `GET /api/sessions/:id/state` (contract first) returns the computed view: per definition `{ definitionId, name, values, meta, warnings, history }`, node implicit keys with the node's label if resolvable, the current turn number, and per turn `{ executionId, turnNumber | null (not present), writes summary }` so the web can show per-message chips and "deleting this undoes …". Server tests: rewind on delete of the last reply, middle delete semantics, multi-reply turns, user-message deletion doesn't undo, failed/stopped turns keep completed writes, definition edits don't rewrite data, 409 rules, contract coverage.
- Change events: `stateDefinitions.changed` (files) ; sessions keep `sessions.changed`.
