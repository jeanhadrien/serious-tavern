# MCP server (plan)

An MCP server so external agents (Claude Desktop, Claude Code, Cursor...) can create and update presets, workflows,
characters and personas. Once built, move these decisions into `apps/mcp/AGENTS.md` and `docs/dev/reference/`, and
delete this file.

## Goal and the one constraint

Adding a feature must not mean maintaining the MCP. The MCP is a generic projection of `apiContract`: it holds no
per-endpoint code, no copied paths and no copied schemas.

What a feature costs, once this is built:
- A new node type or a new field on an entity: nothing (the node catalog and the schemas are already dynamic).
- A new endpoint: one line in the MCP expose map, which typecheck forces.

## Scope (v1)

- Presets: list, get, create, update, preview.
- Workflows: list, get, create, update, validate; node types: list, get one, resolve ports.
- Characters and personas: list, get, create, update.
- Read-only: providers and their models, state definitions, collections.
- Out: delete (later), avatars and card import (later, binary), attaching workflows to chats, secrets.
- Parked: optimistic concurrency with an open editor (`expectedUpdatedAt`), and agents adding HTTP Request nodes to
  workflows already in a chat.

## Decisions

- **The server is the only writer.** The MCP never touches `data/`: workflows, characters and personas announce their
  changes through `NotifyingRepository`, so direct file writes would skip live sync and the route rules.
- **Transport:** stdio first, in its own workspace `apps/mcp`, calling the running server over HTTP. Base URL from an
  env var (default `http://127.0.0.1:3001`); a plain error when the app is not running. Tools don't depend on the
  transport, so a Streamable HTTP entry point can be added later without new tool code.
- **The contract carries `method` and `path`** for every endpoint. Server routes register through a `route(app, key,
  handler)` helper that reads them, so a path has one home. The web client moves onto the contract paths later, in
  its own commit.
- **Tools are generated** from an exhaustive expose/skip map in `apps/mcp`, typed against `ApiEndpoint`: a new endpoint
  fails typecheck until someone decides. The description an agent reads lives in the contract entry.
- **Tool input** is `{ ...params, ...query, body }`. The body stays nested so the path `id` and a record's own `id`
  never collide. Schemas come from `z.toJSONSchema` in input mode; endpoints with a binary body or response are skipped,
  and "no body" (`z.unknown()`) is detected rather than merged as `{}`.
- **Errors:** the API error envelope becomes an MCP tool error carrying `code`, `message` and `details`.
- **Lists are trimmed in the MCP** by one generic rule: each item keeps `id` (or `type`), `name` (or `label`) and
  `description` when present. The agent calls the matching `get_*` for the full record. The API's list responses stay
  as they are (the web relies on full lists). New endpoint `GET /api/node-types/:type`, since the full catalog is
  too large to send on every call.
- **Guides:** a `read_guide(topic)` tool over the user guides (`docs/WORKFLOWS.md`, `PRESETS.md`, `TEMPLATING.md`...),
  plus a short primer in the server's MCP `instructions`. Not MCP resources: clients support them unevenly.

## Work, in commit order

1. Fix: a partial character or persona update wipes the other fields (`.partial()` keeps the inner `.default()`, and
   `updateEntity` merges the defaults over the stored record).
2. Fix: `updateWorkflow` lets the body overwrite `id` and `createdAt`; pin them like the other routes do.
3. Contract `method` and `path`, the `route()` helper, all server routes on it.
4. Workflow create and update report what they dropped and what is invalid: the pruned edge ids and the validation
   issues, as additive response fields. POST prunes like PUT.
5. Node `position` optional in the workflow create and update bodies; the server lays out nodes that have none.
6. `GET /api/node-types/:type` (contract, route, `app.test.ts` coverage in the same commit).
7. `apps/mcp`: the generic projection, the expose map, list trimming, `read_guide`, the base URL setting.
8. Docs: `apps/mcp/AGENTS.md` (and list it in the root `AGENTS.md`), a reference page, a user guide `docs/MCP.md`
   with launch commands per client (on Windows, the absolute `node …/tsx/dist/cli.mjs` path rather than `npx`),
   knip entries.

## Gotchas found while planning

- `superRefine` rules (preset input keys, depth placement) never reach the JSON Schema: agents learn them from errors,
  so those messages must stay plain and precise.
- Preset entry and input ids are re-derived on read: after a save, the agent works from the returned record.
- Node and edge ids are generated by the client: the tool descriptions must say so.
- `previewPreset` takes a full `presetSchema` (uuid, timestamps), awkward for a draft that was never saved.
- Nothing in `apps/mcp` may write to stdout except the transport.
