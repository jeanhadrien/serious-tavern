MESSAGE LINKS AND SUMMARIES AS STORY STATE (STATE-DESIGN-AMENDMENT-1).

SHARED
- Collection items gain the optional built-in `messages: { ids: string[], fingerprint: string }` (not a declared field; every collection accepts it). `collectionItem` (state/node-values.ts) accepts `messages` on an object value: `ids` non-empty strings, `fingerprint` optional at write time. Stored in the `add` write; the fold is unchanged (it already carries items through).
- `linkStatus(item, history)` (pure): `intact | changed | partial | gone`, per the amendment's table; table-tested. One function used by the state view, the turn snapshot and the web model.
- Commit-time link check (generalize `commitSummaryWrites`): for every `add` write whose item has `messages`, against the history messages at commit time: unknown id → drop the write with a warning; `fingerprint` present and not matching → drop with a warning; `fingerprint` absent → compute and store it. A dropped `add` also drops a `remove` written by the same node in the same run when it was its replacement (Save Summary's pair), so a failed replacement never deletes the old summary. Warnings go to the turn entry's `linkWarnings` (capped like `summaryWarnings` was; `.optional().catch(undefined)`) and the run's execution log.
- `planNextChunk(history, items, chunkSize, rawWindow)` and `composeHistory(history, items, lastN)` read items with links (items without `messages` are ignored); "valid" means link status `intact`. The re-planned chunk carries `replaces: <item id>`.
- Remove the phase 6 summary store types and helpers that become unused (knip will tell).

ENGINE
- Turn-start snapshot: collection items carry a read-only computed `link: { status, ids }` when they have `messages` (from `linkStatus` over the run's history). Templates and State Read see it. Never stored.
- **Next Chunk:** config `definitionId` + `key` (a collection key; same picker rules and port resolution style as State Read, an unset/unknown target is a node-not-set-up state like State Read's), `chunkSize`, `rawWindow`; optional `after` input; outputs `messages`, `text`, `chunk` (`{ definitionId, key, ids, fingerprint, replaces? }`), all optional. Plans over that key's folded items.
- **Save Summary:** sink; config none (the target comes from `chunk`) or the same key picker (decide in the plan; the chunk's target must win or match); inputs `chunk` (required) and `text` (required, trimmed, non-empty); writes through `ctx.writeState`: `remove` of `replaces` (if any) and `add { text, messages: { ids, fingerprint } }`. Output `summary` (the item as it will be stored). Delete `SummaryRun` and the summary context fields.
- **Memory:** `summarySet` becomes a key target (`summariesDefinitionId` + `summariesKey`, or one combined field; decide in the plan, keep the panel/form usable without a custom panel if possible, otherwise reuse the State Read key picker). Empty = exactly the old behaviour. Outputs: `history` (unchanged combined output) plus `summaries` (only the used summaries, in the format setting), `recent` (the last N raw messages), `unsummarized` (older messages no used summary covers). New outputs optional, always produced when a key is set.
- Tests: link status on the snapshot; Next Chunk / Save Summary / Memory over state keys (fresh chat, partial chunk, raw window, broken middle summary re-planned, all gone, straddling summary, split outputs); Save Summary's writes undone with the turn (fold); post-part repeated-node rule still drops its writes.

SERVER
- The link check runs inside `settleTurn` and `settlePostRun` on the turn's state writes before they are stored; drop `commitSummaries` and `session.summaries` handling.
- `GET /api/sessions/:id/state` (contract first): collection items that have a link carry `link: { status, count, missing, firstIndex, lastIndex, firstMessageId, lastMessageId }` (1-based indexes among history messages; first/last of the surviving linked messages). Remove `summaries`. Decide in the plan whether linked items' text is sent whole or cut (`previewWrite`) with a way to read the full text on expand (amendment open question 2).
- Tests: commit-time drop (edit and delete during a run, both parts), fingerprint computed when absent (link to the turn's own reply from the post part), replacement pair dropped together, delete of the writing turn undoes the summary and the next turn re-plans it, view link fields.

The separate Summaries section goes away (its model and tests move to the collection rendering).
