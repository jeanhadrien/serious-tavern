# Review lenses

Default set (since phase 5): spec, correctness (with its test check) and, for phases with UI, ui. The
conventions and docs check is part of the verifier's job. The separate conventions and tests lenses below
are kept for phases where they are worth their cost (big refactors, new infrastructure).

- spec: Spec conformance: compare the implementation against the PHASE SPEC and the relevant parts of STATE-DESIGN-PROPOSAL-3. List every missing behaviour, deviation, or half-implemented item. Check the user-facing behaviour described in the spec actually works end to end (engine → server → API → web where applicable).
- correctness: Correctness: hunt for real bugs in the new code. Trace realistic paths from real callers/inputs: edge cases, empty/missing values, error paths, determinism, concurrency and locks (AGENTS.md lock rules), data written to disk, interaction with existing features (streaming turns, stop, message edit/delete, workflow save/validation, presets). For each finding give a concrete failing scenario. Also check that the risky paths you traced are pinned by tests (a test that would fail if the behaviour broke); report missing pins for real risks only. Run `npm test`. Do not report style.
- conventions: Conventions and contracts: check the diff against every relevant rule in AGENTS.md (contract-first API in packages/shared/src/api with server tests, data compatibility/additive schemas, locks via update, canConnect as single source of port rules, macro/hint lists never hand-written, Handlebars templating rules, node-ui never importing web clients, layout rules in apps/web/src/layout, icons lucide with aria-label+title, files < ~250 lines, knip-clean, docs updated: README/AGENTS.md/TEMPLATING.md). Also check maintainability: duplication with existing helpers, naming, needless complexity.
- tests: Tests: evaluate whether the new tests actually pin the behaviour in the spec. Find untested behaviours, tests that would pass even if the feature were broken, missing failure-path and edge-case tests, and missing contract coverage (app.test.ts requires every endpoint exercised). Run `npm test` and report failures.
- ui: Live UI check: run the server (temp data dir per the ground rules) and the web dev server pointed at it, then use Playwright (Chromium at /opt/pw-browsers) to exercise every new or changed UI flow of this phase as a user would, at desktop 1400x900 and phone 390x844. Check: it renders, controls work, values persist after reload, errors are shown sensibly, nothing existing broke (open chat, workflow editor, presets). Save screenshots to <scratch>/shots/phase-<N>/review/. Report concrete broken behaviours as findings. Clean up processes and temp dirs.
